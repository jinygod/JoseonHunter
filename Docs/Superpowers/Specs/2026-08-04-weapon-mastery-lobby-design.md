# 무기 숙련 연구소와 기능형 로비 설계

## 1. 목적

현재 전투는 한 판 안의 조합과 선택 재미를 갖췄다. 다음 단계의 목표는
플레이어가 한 판을 마친 뒤 `다음에는 다른 무기 운용법을 시험하겠다`는
명확한 이유를 갖게 만드는 것이다.

영구 성장은 순수 화력 누적보다 새로운 운용법 해금을 중심으로 한다.
무기별 마지막 일격이 숙련도를 만들고, 충분한 숙련도를 채운 뒤 엽전을
지불하면 새 운용법을 장착할 수 있다. 로비는 당장 사용하는 기능만 남겨
`무기 연구`, `출전`, `공통 수련`의 세 메뉴로 구성한다.

## 2. 확정된 제품 원칙

- 숙련도의 주된 보상은 수치가 아니라 새로운 무기 운용법이다.
- 무기별 숙련도는 해당 무기의 마지막 일격으로만 오른다.
- 승리, 패배, 직접 중도 포기 모두 실제 획득 숙련도와 엽전을 100% 저장한다.
- 무기마다 기본형을 포함한 고정 운용법 세 개를 제공한다.
- 출전 전에 시작 무기와 무기별 운용법을 선택한다.
- 숙련 요구량을 채워도 운용법이 자동 해금되지 않는다. 엽전 구매가 필요하다.
- 엽전은 운용법 구매와 소규모 공통 능력 강화가 공유한다.
- 로비에는 확실히 사용하는 메뉴만 노출하며 이후 기능을 하나씩 확장한다.
- 새로운 전투 동작 24개를 만들지 않고, 이미 구현된 기본형과 전승 경로를
  숙련 운용법으로 재사용한다.

## 3. 구현 범위

이번 기능 묶음에 포함한다.

1. 기능형 `Lobby` 장면과 세 메뉴
2. 무기별 처치 귀속 및 런 단위 숙련 정산
3. 무기 숙련 진행과 엽전 최종 해금
4. 무기 8종의 기본형 및 기존 전승 2종 장착
5. 출전 설정 세 개와 시작 무기 선택
6. 소규모 공통 수련
7. 기존 저장 파일을 보존하는 저장 데이터 마이그레이션
8. 전투 시작과 종료 시 로비-게임플레이 왕복 흐름
9. 로비용 PixelLab 배경과 기존 에셋 재사용

이번 기능 묶음에서 제외한다.

- 상점
- 수사록 화면
- 영웅 수집과 영웅별 시작 무기 제한
- 무작위 상자나 유료 재화
- 노바1492식 자유 파츠 조립
- 신규 무기
- 무한 숙련 레벨과 반복 수치 보너스

## 4. 사용자 흐름

### 4.1 첫 진입

`Bootstrap`은 저장 데이터를 불러온 뒤 `Lobby`로 이동한다. 로비 기본 메뉴는
`출전`이다. 기존 저장 파일에는 환도 기본형이 장착된 첫 번째 설정을 자동으로
만든다.

### 4.2 출전 준비

플레이어는 세 출전 설정 중 하나를 선택한다. 설정은 다음 데이터를 가진다.

- 사용자 지정 가능한 설정 이름
- 시작 무기 한 개
- 무기 8종 각각의 장착 운용법
- 난이도

잠긴 운용법은 표시하되 선택할 수 없다. 시작 무기는 현재 콘텐츠에 등록된
무기 8종 중 하나를 선택할 수 있다. 출전 버튼은 현재 설정을 저장한 다음
`Gameplay`을 연다.

### 4.3 전투

시작 무기는 런 시작 시 바로 획득한다. 이후 다른 무기를 얻으면 현재 출전
설정에 저장된 운용법을 사용한다. 장착된 운용법은 무기 획득 시점부터
적용한다.

기존 3레벨 전승 선택은 메타 장착과 중복되므로 제거한다. 해당 레벨은
일반 무기 강화 또는 다른 성장 선택으로 대체한다. 잠재 옵션, 조합 반응,
레벨업 선택은 유지한다.

### 4.4 정산과 복귀

각 적이 사망할 때 최종 피해 요청의 무기 ID에 처치 점수를 귀속한다.
런 중에는 메모리 원장에만 누적하고, 결과 확정 시 한 번에 저장한다.

정산 순서는 다음과 같다.

1. 무기별 숙련 점수 반영
2. 새 연구 완료 상태 계산
3. 런에서 획득한 엽전 반영
4. 최고 기록 갱신
5. 저장 성공
6. 결과 화면 표시
7. 확인 시 로비 복귀

중도 포기도 동일한 정산 경로를 사용한다. 실제로 얻지 않은 보상을 만들지
않으며, 이미 얻은 숙련도와 엽전을 삭감하지 않는다.

## 5. 로비 정보 구조

### 5.1 공통 프레임

세로 기준 화면으로 구성한다.

- 상단: 화면 제목, 보유 엽전, 구매 가능한 연구 알림 수
- 중앙: 현재 메뉴 콘텐츠
- 하단: `무기 연구`, `출전`, `공통 수련` 세 버튼
- 기본 선택: `출전`

하단 `출전`은 중앙의 주요 행동으로 조금 더 크게 표시한다. 텍스트는 전부
한글을 사용한다. 제목은 정돈된 궁서 계열, 정보와 설명은 마루 부리를
사용한다.

### 5.2 출전 메뉴

- 기존 포졸 로비 캐릭터
- 현재 설정 번호와 이름
- 시작 무기 아이콘, 이름, 장착 운용법
- 현재 난이도와 최고 기록
- 이전/다음 설정 버튼
- 설정 편집 버튼
- 큰 `출전` 버튼

### 5.3 무기 연구 메뉴

상단 또는 좌측의 무기 목록에서 한 개를 고르면 상세 패널을 갱신한다.

- 무기 아이콘과 이름
- 누적 숙련 점수
- 다음 연구까지 남은 점수
- 진행 막대
- 기본형, 전승 1, 전승 2 카드
- 각 운용법의 장점과 단점
- 연구 완료 여부
- 엽전 비용과 `해금` 버튼
- 현재 설정에 장착하는 버튼
- 누적 처치와 보스 마무리 기록

잠금 상태를 색만으로 전달하지 않는다. `연구 중`, `해금 가능`, `해금 완료`,
`장착 중` 문구를 함께 쓴다.

### 5.4 공통 수련 메뉴

수련 항목은 여섯 개다.

| 항목 | 단계 효과 | 최대 단계 | 최대 효과 |
| --- | ---: | ---: | ---: |
| 활력 | 최대 체력 +2% | 5 | +10% |
| 완력 | 전체 무기 피해 +2% | 5 | +10% |
| 보법 | 이동 속도 +2% | 5 | +10% |
| 학습 | 경험치 획득량 +2% | 5 | +10% |
| 호신 | 받는 피해 -2% | 5 | -10% |
| 감응 | 경험치 획득 범위 +2% | 5 | +10% |

단계 비용은 `100, 180, 280, 420, 600` 엽전이다. 구매 전 현재 값과 구매 후
값을 함께 보여준다. 공통 수련은 무료 초기화를 지원하고, 초기화하면 사용한
엽전을 전부 돌려준다.

## 6. 숙련 규칙

### 6.1 처치 점수

| 대상 | 숙련 점수 |
| --- | ---: |
| 일반 몬스터 | 1 |
| 특수 몬스터 | 3 |
| 정예 몬스터 | 10 |
| 중간 보스 | 30 |
| 최종 보스 | 100 |

최종 일격을 넣은 무기만 점수를 얻는다. 환경 피해, 금줄, 상태 지속 피해처럼
피해 요청에 무기 ID가 없는 공격은 무기 숙련도를 주지 않는다. 전투 로그와
결과 화면의 합계는 동일한 원장을 사용한다.

### 6.2 운용법 요구량과 가격

| 운용법 | 숙련 요구량 | 엽전 비용 |
| --- | ---: | ---: |
| 기본형 | 0 | 0 |
| 전승 1 | 2,000 | 800 |
| 전승 2 | 8,000 | 2,400 |

요구량은 초기 기준값이다. 마지막 일격 분포를 실제 플레이 데이터로 측정한
뒤, 첫 전승이 주력 무기로 약 8~10판에 열리도록 무기별 요구량만 조정할 수
있다. 가격과 요구량은 콘텐츠 데이터에서 관리하고 저장 파일에 복제하지
않는다.

점수가 요구량을 넘으면 초과분을 보존한다. 엽전이 부족하면 상태는
`해금 가능`으로 남고 숙련 점수는 계속 누적된다. 구매 시 숙련 점수를
소비하지 않는다.

### 6.3 기존 전승 재사용

| 무기 | 전승 1 | 전승 2 |
| --- | --- | --- |
| 환도 비검 | 월식 | 맹독 |
| 각궁 | 갈래 깃 | 태양 관통 |
| 서리병 | 서리 안개 | 빙결 파쇄 |
| 벽력탄 | 지맥 전류 | 뇌옥 |
| 풍뢰선 | 진공 | 천뢰 |
| 장승진 | 사방 수호 | 수호령 강림 |
| 신기전 | 화룡 | 화망 |
| 주술 부적 | 귀기 폭발 | 천부인 |

각 전승은 장점과 단점을 함께 표시한다. 동일 무기의 세 운용법은 상위·하위
관계가 아니라 공격 범위, 빈도, 단일 대상, 군중 제어가 갈리는 선택지다.

## 7. 데이터와 코드 경계

### 7.1 콘텐츠 데이터

`WeaponMasteryCatalog`가 다음을 소유한다.

- 무기 ID
- 표시 이름과 아이콘
- 운용법 세 개의 ID, 이름, 설명
- 장점과 단점
- 숙련 요구량
- 엽전 비용
- 기존 전승 경로 매핑

### 7.2 런 원장

`RunWeaponKillLedger`는 한 런의 무기별 숙련 점수만 소유한다. 피해 서비스의
확정된 사망 이벤트를 받아 마지막 일격 무기와 적 등급을 기록한다. UI나 저장
저장소를 직접 알지 않는다.

### 7.3 영구 진행

`WeaponMasteryProgression`은 누적 점수, 구매 가능 여부, 해금 구매를 처리한다.
엽전 차감과 운용법 해금은 복사본에서 검증 후 한 번에 반영한다.

`CommonTrainingProgression`은 여섯 수련 항목의 구매, 최대 단계, 비용, 무료
초기화를 처리한다.

### 7.4 출전 설정

`PatrolLoadout`은 시작 무기, 무기별 운용법, 난이도를 가진다. 세 설정은 저장
데이터에 보존한다. 잘못된 무기나 운용법 ID를 읽으면 해당 무기의 기본형으로
정규화한다.

### 7.5 프레젠테이션

로비 프레젠터는 저장 데이터를 직접 변경하지 않는다. 조회 모델을 렌더링하고
구매, 장착, 출전 명령을 애플리케이션 서비스에 전달한다. 로비 장면에는 다음
구조가 실제로 존재해야 한다.

- `Lobby Camera`
- `Lobby Canvas`
- `EventSystem`
- `Lobby Root`
- `Header`
- `Patrol Panel`
- `Weapon Research Panel`
- `Common Training Panel`
- `Bottom Navigation`
- `Lobby Bootstrap`

런타임 생성 UI를 사용하더라도 이 상위 구조는 씬과 Hierarchy에서 확인할 수
있게 한다.

## 8. 저장 마이그레이션

저장 스키마를 2로 올리고 다음 데이터를 추가한다.

- 무기별 누적 숙련 점수
- 해금된 운용법 ID 집합
- 공통 수련 단계와 사용 엽전
- 출전 설정 세 개
- 현재 출전 설정 번호

스키마 1 저장을 불러오면 기존 엽전, 장비, 진화, 수사, 설정 데이터를 그대로
복사하고 신규 필드만 기본값으로 채운다. 마이그레이션은 반복 실행해도 결과가
같아야 한다. 손상되거나 일부 필드가 빠진 저장은 필수 기본값을 정규화한다.

자동 저장 트리거는 다음을 포함한다.

- 런 결과와 중도 포기 정산
- 운용법 구매
- 운용법 장착과 출전 설정 변경
- 공통 수련 구매와 초기화
- 앱 일시 중단

## 9. 장면 전환

- `Bootstrap` → 저장 로드 → `Lobby`
- `Lobby` 출전 → 선택 설정 저장 → `Gameplay`
- `Gameplay` 승리/패배 결과 확인 → 정산 저장 → `Lobby`
- `Gameplay` 중도 포기 → 정산 저장 → `Lobby`

장면 이름은 중앙 라우팅 계층에서 관리한다. 중복 클릭으로 출전이 두 번
시작되지 않도록 전환 중에는 버튼 입력을 잠근다. 저장 실패 시 Gameplay을
열거나 로비로 이동하지 않고 한글 오류 안내와 재시도 버튼을 제공한다.

## 10. 시각 설계와 에셋

PixelLab으로 로비 배경 한 장을 제작한다.

- 9:16 세로 배경
- 조선 관아의 단정한 마당 또는 툇마루
- 탁한 흙색, 먹색, 옅은 청록 중심의 제한된 팔레트
- 흰 외곽선 금지
- 중앙 캐릭터와 텍스트 뒤는 단순한 면으로 유지
- 이미지 내부에 글자, 버튼, UI 프레임을 그리지 않음
- 먼 카메라에서도 형태가 읽히는 큼직한 픽셀 덩어리

기존 `rookie_constable.png`, 무기 아이콘, 전승 아이콘을 재사용한다. 패널과
버튼은 런타임 단색 한지·먹색 UI로 만든다. 장식 이미지를 과도하게 늘리지
않고, 글자 대비와 안전 영역을 우선한다.

## 11. 오류 처리

- 숙련 부족: 버튼 비활성화와 남은 점수 표시
- 엽전 부족: 현재 엽전, 필요 엽전, 부족분 표시
- 이미 해금됨: 중복 차감 없이 성공 상태 유지
- 잠긴 운용법 장착 요청: 거부하고 기존 설정 유지
- 존재하지 않는 콘텐츠 ID: 기본형으로 정규화하고 오류 로그 기록
- 저장 실패: 라이브 데이터를 변경하지 않고 재시도 가능 상태 유지
- 장면 전환 실패: 현재 장면을 유지하고 입력 잠금을 해제

## 12. 성능 원칙

- 로비에서는 전투 런타임과 몬스터·무기 실행기를 생성하지 않는다.
- 무기 목록은 고정 8개를 재사용하며 매 프레임 재생성하지 않는다.
- 숙련 정산은 적 사망 이벤트에서 정수 누적만 하고 저장은 런 종료 시 한 번
  수행한다.
- 배경은 한 장의 압축 텍스처로 사용하고 UI 애니메이션은 단순한 위치·크기·
  알파 변화로 제한한다.
- 씬 전환 중 중복 로드와 중복 저장을 방지한다.

## 13. 테스트와 검증

### EditMode

- 마지막 일격 무기만 숙련 점수를 받는다.
- 적 등급별 점수가 정확하다.
- 패배와 중도 포기도 100% 정산한다.
- 숙련 요구량과 엽전 조건을 모두 만족해야 구매된다.
- 실패한 구매는 데이터와 엽전을 변경하지 않는다.
- 초과 숙련 점수가 보존된다.
- 출전 설정은 잠긴 운용법을 거부한다.
- 공통 수련 최대 단계, 비용, 무료 초기화가 정확하다.
- 스키마 1 저장이 스키마 2로 손실 없이 변환된다.

### PlayMode

- Bootstrap이 Lobby를 연다.
- 세 메뉴만 표시되고 각 메뉴 전환이 동작한다.
- 시작 무기와 운용법을 선택하고 Gameplay에 전달한다.
- 설정한 시작 무기가 런 시작 시 등록된다.
- 획득한 무기가 장착 운용법을 사용한다.
- 결과 확인과 중도 포기가 정산 후 Lobby로 돌아온다.
- 구매·장착 후 씬을 다시 열어도 상태가 유지된다.
- 세로 안전 영역과 주요 버튼의 글자가 읽힌다.

### 시각·빌드

- PixelLab 배경을 Unity에서 Point 필터와 의도한 압축 설정으로 확인한다.
- 9:16 Game View에서 세 메뉴와 긴 한글 문구의 겹침을 확인한다.
- 전체 EditMode와 PlayMode 테스트를 실행한다.
- Android ARM64 IL2CPP 개발 APK를 생성한다.

## 14. 완료 기준

- 앱을 시작하면 빈 장면이 아니라 기능형 로비가 표시된다.
- 화면 하단에는 세 메뉴만 보인다.
- 플레이어가 시작 무기와 운용법을 고르고 출전할 수 있다.
- 마지막 일격이 정확한 무기의 숙련도로 누적된다.
- 모든 종료 경로에서 숙련도와 엽전이 보존된다.
- 숙련 완료 후 엽전 구매로 운용법을 해금하고 장착할 수 있다.
- 여섯 공통 수련을 구매하고 무료 초기화할 수 있다.
- 기존 저장 파일을 잃지 않는다.
- 전투 결과 확인 후 로비로 복귀한다.
- 전체 자동 테스트와 Android 빌드가 통과한다.

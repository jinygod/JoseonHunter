## 1. 목표

한 판의 성과가 로비의 장기 성장으로 이어지도록 계정 레벨을 추가한다. 계정 레벨은 로비 좌측 상단에서 항상 확인할 수 있으며, 영구 성장 메뉴인 `수련`의 총 투자 가능 횟수를 제한한다.

- 계정 최고 레벨은 100이다.
- 수련은 전체 합산 최대 100강이다.
- 계정 레벨 1당 수련 한도가 5강씩 열린다.
- 계정 레벨 1에서는 총 5강, 레벨 20에서는 총 100강까지 투자할 수 있다.
- 계정 레벨 21~100은 향후 콘텐츠 해금과 장기 진행을 위한 성장 축으로 남긴다.
- 기존 저장 데이터의 엽전, 무기 숙련도, 수련 단계와 소비 엽전은 보존한다.

이번 범위에는 계정명 변경, 소셜 기능, 클라우드 저장, 계정 레벨 보상 상자, 레벨 20 이후의 추가 수련 한도 확장은 포함하지 않는다.

## 2. 현재 구조와 확장 지점

기존 구조를 교체하지 않고 다음 지점을 확장한다.

- `SaveDataV1`: 계정 누적 경험치 저장 필드를 추가하고 스키마를 3으로 올린다.
- `JsonSaveRepository`: 스키마 1·2를 3으로 이관하고 체크섬이 적용된 문서를 저장한다.
- `RunSettlement`: 현재 플레이 시간, 처치 수, 승패, 포기 여부로 계정 경험치를 계산할 입력을 이미 제공한다.
- `AutoSaveOrchestrator.CommitRun`: 엽전·숙련도·최고 기록과 같은 원자적 저장 트랜잭션 안에서 계정 경험치도 함께 반영한다.
- `CommonTrainingProgression`: 트랙별 한도, 총 수련 한도, 비용과 효과 계산을 확장한다.
- `LobbyBootstrap` 및 `CommonTrainingPresenter`: 로비 계정 정보와 수련 진행 상태를 표시한다.
- `RunResultPresenter`: 한 판에서 획득한 계정 경험치와 계정 레벨 상승을 표시한다.

계정 레벨과 수련 수치는 순수 도메인 계산으로 구현하여 Unity 화면 없이 EditMode 테스트에서 검증할 수 있게 한다.

## 3. 계정 경험치 획득

### 3.1 한 판 보상

정상 종료한 한 판의 계정 경험치는 다음과 같이 계산한다.

```text
플레이 경험치 = min(floor(생존 초 / 6), 150)
처치 경험치   = min(floor(처치 수 / 4), 200)
승리 경험치   = 승리 시 250, 그 외 0
기본 획득량   = 플레이 경험치 + 처치 경험치 + 승리 경험치
```

- 15분 생존으로 플레이 경험치 최대 150을 얻는다.
- 800처치부터 처치 경험치 최대 200을 얻는다.
- 승리까지 포함한 한 판 최대치는 600이다.
- 전투 중 귀환하거나 포기한 경우 `floor(기본 획득량 × 0.25)`만 지급한다.
- 패배했지만 포기하지 않은 정상 정산은 승리 경험치만 제외하고 플레이·처치 경험치를 온전히 지급한다.
- 음수 시간과 음수 처치 수는 0으로 정규화한다.

### 3.2 레벨 요구 경험치

현재 계정 레벨을 `L`이라 할 때 다음 레벨까지 필요한 경험치는 다음과 같다.

```text
필요 경험치(L) = 100 + 40 × (L - 1) + 2 × (L - 1)²
```

- 계정은 레벨 1, 현재 경험치 0에서 시작한다.
- 경험치는 누적값으로 저장하며 여러 레벨을 한꺼번에 오를 수 있다.
- 레벨 20 도달에 필요한 누적 경험치는 12,958이다.
- 최대 레벨 100에 도달하면 누적 경험치는 레벨 100 도달 누적치로 고정한다.
- 로비 진행 바는 현재 레벨 시작 누적치부터 다음 레벨 누적치 사이의 진행률을 표시한다.
- 최대 레벨에서는 진행 바를 가득 채우고 `최대 레벨`로 표시한다.

이 곡선은 초반에는 계정 레벨 상승을 자주 보여주되, 레벨이 높아질수록 장기 목표가 되도록 설계한다. 완전 승리 기준 계정 레벨 20은 대략 20~25판 사이에 도달한다.

## 4. 수련 확장과 계정 레벨 제한

### 4.1 전체 및 트랙 한도

수련 트랙은 기존 여섯 종류를 유지한다.

1. 활력
2. 완력
3. 보법
4. 학습
5. 수호
6. 공명

각 트랙은 최대 20강이며, 전체 투자 한도는 다음과 같다.

```text
현재 총 수련 한도 = min(계정 레벨 × 5, 100)
현재 총 수련 단계 = 여섯 트랙 단계의 합
```

- 계정 레벨 1: 총 5강
- 계정 레벨 7: 총 35강
- 계정 레벨 10: 총 50강
- 계정 레벨 20 이상: 총 100강
- 트랙 전체를 모두 최고 단계로 만들려면 120강이 필요하지만 실제 한도는 100강이므로 20강의 기회비용이 생긴다.
- 초기화 시 투자한 수련 단계와 그 단계에 실제 소비한 엽전을 전부 되돌린다.

### 4.2 단계별 효과

모든 트랙은 동일한 완만한 체감 곡선을 사용한다.

```text
1~5강:   단계당 +2.0%  (5강 누적 +10%)
6~10강:  단계당 +0.6%  (10강 누적 +13%)
11~20강: 단계당 +0.2%  (20강 누적 +15%)
```

- 활력: 최대 체력 증가
- 완력: 공격 피해 증가
- 보법: 이동 속도 증가
- 학습: 경험치 획득량 증가
- 수호: 받는 피해 감소
- 공명: 전리품 및 경험치 획득 반경 증가

기존 1~5강 효과는 단계당 2%로 그대로 유지한다. 따라서 이관된 사용자의 현재 전투 성능은 바뀌지 않는다. 수호는 다른 트랙과 반대 방향으로 적용하여 20강에서 받는 피해가 15% 감소한다.

### 4.3 강화 비용

다음 단계 `n`을 구매할 때의 비용은 다음과 같다.

```text
1강 100
2강 180
3강 280
4강 420
5강 600

6~20강:
d = n - 5
비용(n) = 600 + 35 × d + 8 × d²
```

예시는 다음과 같다.

- 6강: 643 엽전
- 10강: 975 엽전
- 15강: 1,750 엽전
- 20강: 2,925 엽전
- 한 트랙 1~20강 총비용: 24,700 엽전

초반 기존 비용은 보존하고, 후반 단계는 계정 레벨과 함께 장기 목표가 되도록 점진적으로 증가시킨다.

## 5. 구매 규칙과 오류 처리

수련 구매는 다음 순서로 검증한다.

1. 알려진 수련 트랙인지 확인한다.
2. 해당 트랙이 20강 미만인지 확인한다.
3. 현재 총 수련 단계가 계정 레벨 한도보다 낮은지 확인한다.
4. 다음 단계 비용만큼 엽전이 있는지 확인한다.
5. 수련 단계와 누적 소비 엽전 계산에 정수 오버플로가 없는지 확인한다.
6. 복사본에 모든 변경을 적용한 뒤 한 번에 원본에 반영한다.

실패 시 엽전, 단계, 소비 기록 어느 것도 변경하지 않는다. 계정 레벨 한도에 걸리면 다음 해금 레벨을 계산해 `계정 레벨 8에서 추가 수련이 열립니다`처럼 안내한다.

## 6. 저장 스키마와 이관

저장 스키마를 3으로 올리고 `AccountExperience` 누적 정수 값을 추가한다.

### 6.1 신규 저장

- 계정 레벨 1
- 계정 경험치 0
- 기존 신규 계정 기본 엽전·숙련도·수련 값 유지

### 6.2 스키마 1·2 이관

스키마 1과 2의 정상 저장을 계속 읽는다. 계정 경험치가 없으므로 현재 총 수련 단계를 기준으로 최소 계정 레벨을 보장한다.

```text
필요 최소 레벨 = clamp(ceil(현재 총 수련 단계 / 5), 1, 20)
이관 계정 경험치 = 필요 최소 레벨 시작 누적 경험치
```

예를 들어 기존 총 수련이 17강이면 계정 레벨 4의 시작 경험치로 이관한다. 이 방식으로 기존에 합법적으로 구매한 수련이 계정 레벨 제한 때문에 잠기지 않는다.

- 기존 엽전, 무기 숙련도, 연구 해금, 수련 단계, 수련 소비 엽전, 최고 기록은 그대로 복사한다.
- 각 기존 수련 트랙은 당시 최대치인 5강 이하이므로 새 트랙 최대치 20 안에 자연스럽게 들어간다.
- 기존 수련 1~5강 효과와 비용을 유지하므로 이관 직후 능력치와 초기화 환급액이 달라지지 않는다.
- 스키마 3 저장은 계정 경험치를 0 이상, 최대 레벨 누적치 이하로 정규화한다.
- 체크섬이 맞지 않는 저장은 기존 저장소 정책대로 손상된 저장으로 처리한다.

## 7. 원자적 한 판 정산

`CommitRun`은 다음 항목을 하나의 트랜잭션으로 처리한다.

- 엽전 획득
- 무기별 숙련도 획득
- 계정 경험치 획득
- 최고 생존 시간 및 최고 처치 기록 갱신

먼저 현재 데이터를 복사하고 모든 보상과 레벨 계산을 복사본에서 완료한다. 값 검증 또는 저장에 실패하면 원본 메모리 데이터도 변경하지 않는다. 저장 성공 후에만 복사본을 현재 데이터로 확정한다.

정산 결과에는 다음 UI 표시용 값을 함께 반환한다.

- 획득 계정 경험치
- 정산 전 계정 레벨
- 정산 후 계정 레벨
- 최대 레벨 도달 여부

## 8. 로비 UI

### 8.1 좌측 상단 계정 정보

기존 로비 상단 제목 영역의 좌측을 모바일 게임형 계정 정보 블록으로 바꾼다.

- 작은 장식 액자 안에 계정 레벨 숫자를 표시한다.
- 액자 오른쪽에 `요괴 사냥꾼` 계정 명칭을 표시한다.
- 아래에 초록색 계정 경험치 진행 바를 배치한다.
- 진행 바에는 `현재 경험치 / 다음 레벨 필요 경험치`를 표시한다.
- 최대 레벨에서는 `최대 레벨`을 표시한다.
- 우측의 픽셀 엽전 아이콘과 보유 엽전 표시는 유지한다.

현재 로비는 픽셀 아트 배경과 단정한 조선풍 UI를 사용하므로, 새 실사 캐릭터 이미지나 별도 AI 이미지를 추가하지 않는다. 작은 계정 배지는 기존 UI 도형과 장식 자원으로 구성한다.

### 8.2 수련 메뉴

수련 화면 상단에 다음 정보를 표시한다.

```text
총 수련 24/35 · 계정 7레벨 한도
```

각 트랙 버튼은 `활력 8/20`처럼 현재 단계와 트랙 최대 단계를 표시한다. 선택한 트랙 상세 영역에는 다음을 표시한다.

- 현재 효과: `최대 체력 +11.8%`
- 다음 효과: `12.4%`
- 다음 강화 비용
- 강화 후 남는 엽전

총 수련 한도에 도달하면 강화 버튼을 비활성화하고 다음 한도가 열리는 계정 레벨을 구체적으로 안내한다. 트랙이 20강이면 `최고 단계`로 표시한다.

## 10. 테스트 전략

구현은 테스트 우선으로 진행한다.

### EditMode

- 한 판 경험치: 0값, 일반 패배, 승리, 최대치, 포기 25%, 음수 입력 정규화

- 로비 계정 레벨, 경험치 바, 엽전 표시

- 결과창의 획득 계정 경험치와 레벨 상승 표시
- 로비 재진입 후 저장된 계정 정보가 동일하게 복원되는지 확인

- Unity PlayMode 테스트 전체 실행

## 11. 완료 조건

- 신규 계정이 레벨 1·경험치 0으로 시작한다.
- 한 판 정산마다 승인된 공식으로 계정 경험치가 원자적으로 저장된다.
- 계정 레벨 1에서 총 수련 5강, 레벨 20에서 100강까지 구매할 수 있다.
- 각 수련 트랙은 최대 20강이며 모든 트랙 합계는 100강을 넘지 않는다.
- 20강 효과는 각 트랙 기준 최대 15%이고, 기존 1~5강 성능은 바뀌지 않는다.
- 기존 저장은 현재 구매한 수련을 잃거나 잠그지 않고 스키마 3으로 이관된다.
- 로비 좌측 상단에서 계정 레벨과 경험치 진행을 한눈에 확인할 수 있다.
- 수련 화면과 결과 화면의 모든 정보가 한글로 명확히 표시된다.
- 관련 EditMode·PlayMode 테스트와 batchmode 검증이 통과한다.

# 전투 모션 완성도 폴리싱 설계

작성일: 2026-07-29  
상태: 사용자 방향 승인 완료

## 1. 목표

현재의 정지 스프라이트가 직선으로 미끄러지는 인상을 제거한다. 주인공, 일반 몬스터,
엘리트, 보스와 8종 무기는 각자의 무게와 리듬이 느껴지도록 움직여야 한다. 시각적
애니메이션은 기존의 픽셀 단위 공격 판정, 공격 인스턴스, 무기 성장 규칙을 변경하지
않는다.

완료된 전투는 다음 감각을 제공해야 한다.

- 주인공은 입력 시작과 정지, 방향 전환에 관성과 발 디딤이 느껴진다.
- 같은 종류의 몬스터가 무리를 이루더라도 동시에 같은 동작을 반복하지 않는다.
- 일반, 엘리트, 보스가 크기뿐 아니라 보폭과 반응 속도로도 구분된다.
- 투사체가 등속 직선 이동하는 임시 오브젝트처럼 보이지 않는다.
- 공격이 실제 픽셀에 닿은 순간에만 피격 반응, 접촉 섬광과 피해 숫자가 발생한다.
- 화면 흔들림과 히트 스톱은 강한 공격에만 사용해 가독성을 보존한다.

## 2. 선택한 접근

다중 프레임 픽셀 애니메이션과 절차적 마이크로 모션을 결합한다.

프레임 애니메이션은 실루엣과 팔다리 변화처럼 그림 자체가 바뀌어야 하는 동작을
담당한다. 절차적 모션은 가속, 기울기, 착지 압축, 피격 반동, 잔상, 카메라 추적처럼
여러 캐릭터에 일관되게 적용할 수 있는 움직임을 담당한다.

전부 절차적으로 흔드는 방식은 제작은 빠르지만 종이 인형 같은 인상을 남긴다. 모든
개체에 많은 방향과 동작을 제작하는 방식은 첫 폴리싱 범위에 비해 비용이 크다.
하이브리드 방식은 화면에서 가장 자주 보이는 동작에 PixelLab 생성량을 집중한다.

## 3. 판정 루트와 비주얼 피벗

모든 움직이는 전투 개체는 다음 구조를 사용한다.

```text
Logical Root
├─ Visual Pivot
│  └─ SpriteRenderer
└─ World UI / Health Bar
```

- `Logical Root`는 이동 좌표, 타깃 등록, 공격 판정과 접촉 거리의 소유자다.
- `Visual Pivot`만 걷기 바운스, 기울기, 스쿼시, 피격 반동과 사망 연출을 적용받는다.
- 프레임 교체는 `SpriteRenderer.sprite`만 변경한다.
- 픽셀 마스크 계산은 시각적 스쿼시나 바운스를 물려받지 않는 안정된 논리 변환을
  사용한다.
- 체력바는 비주얼 피벗의 회전과 스쿼시를 상속하지 않는다.

이 분리는 모션을 풍부하게 하면서도 “보이는 픽셀과 판정이 어긋나는” 문제를 막는
핵심 계약이다.

## 4. PixelLab 애니메이션 제작 범위

런타임에서 사용하는 파일은 계속 `한 PNG = 한 프레임 에셋` 규칙을 지킨다.
스프라이트 시트나 여러 에셋이 붙은 접촉 시트는 사용하지 않는다.

### 주인공 한연화

- 4방향 걷기: 방향당 6프레임
- 4방향 대기: 방향당 3프레임
- 피격: 방향당 1개의 보조 프레임 또는 공용 2프레임
- 기존 색상, 얼굴, 의상과 실루엣을 유지한다.

### 일반 몬스터 5종

- 종류별 좌우 보행 4프레임을 기본으로 한다.
- 좌우 대칭이 자연스러운 종류는 한 방향을 반전해 사용한다.
- 몸체 방향이 중요한 종류만 상하 또는 추가 방향 프레임을 제작한다.
- 각 개체는 생성 시 애니메이션 시작 위상과 보폭을 조금 다르게 가진다.

### 엘리트와 보스

- 엘리트: 보행 4프레임, 대기 3프레임, 공격 예고 2프레임.
- 보스: 보행 6프레임, 대기/호흡 4프레임, 공격 예고 3프레임, 피격 2프레임.
- 큰 개체일수록 재생 속도는 느리고 착지 압축과 화면 반응은 강하다.

생성 후보는 먼저 기존 대표 스프라이트와 동일한 캐릭터로 검수한다. 실패한 변형을
무제한 재생성하지 않고 캐릭터별로 일관성 있는 세트를 선택한다. 최종 채택 프레임과
생성 작업 ID는 PixelLab 원장에 기록한다.

## 5. 캐릭터 모션

### 주인공

- 입력은 즉시 방향을 바꾸되 표시 속도는 짧은 가속과 감속을 거친다.
- 걷기 프레임은 실제 이동 속도에 비례해 재생한다.
- 좌우 이동에는 최대 약 3도의 기울기를 주고 정지 시 빠르게 복원한다.
- 발이 닿는 프레임에 작은 하강과 압축을 넣는다.
- 대기 중에는 느린 호흡만 남기고 지속적인 큰 바운스는 사용하지 않는다.

### 몬스터

- 목표 추적 방향은 논리적으로 유지하되 표시 회전과 기울기는 부드럽게 따라간다.
- 개체별 위상, 보폭, 재생 속도를 분산해 군집 동기화를 제거한다.
- 일반 몬스터는 빠르고 작은 반응, 엘리트는 느리고 큰 반응, 보스는 가장 무겁고
  절제된 반응을 사용한다.
- 피격 시 접촉점 반대 방향으로 비주얼 피벗만 짧게 밀리고 복귀한다.
- 사망 시 즉시 삭제하지 않고 짧은 정지, 기울어짐, 축소/용해 후 논리 개체를
  정리한다. 보상은 판정상 사망 시점에 즉시 생성한다.

## 6. 무기 모션

8종 무기의 공격 판정과 개성은 유지하면서 표시 곡선만 개선한다.

- 환도 비검: 출발 가속, 목표 근처 감속, 곡선 편향, 회수 시 다른 곡선과 잔상.
- 각궁: 짧은 조준 긴장, 초반 가속, 미세한 궤도 편차, 접촉 파편.
- 부적: 가벼운 부유와 회전, 연쇄 시 다음 목표로 휘어지는 경로.
- 벽력탄: 상승과 하강이 구분되는 포물선, 착지 직전 그림자 압축.
- 장승: 땅에서 솟는 오버슈트와 정착, 수호 범위의 느린 호흡.
- 신기전: 발사 순서와 낙하 시간 분산, 착탄 직전 가속.
- 서리병: 투척 회전과 포물선, 착지 충격 후 서리 영역 확장.
- 풍뢰부채: 부채질 방향성, 바람 전파의 지연, 번개 연결의 짧은 단계 차이.

투사체의 시각적 위치와 판정 위치가 달라지지 않도록 이동 곡선의 실제 위치에서
마스크 접촉을 검사한다. 잔상과 장식만 판정에서 제외한다.

## 7. 전투 피드백과 카메라

- 일반 적중은 피격 프레임, 작은 접촉 섬광과 피해 숫자만 사용한다.
- 치명타, 처치, 진화 무기 강타에만 짧은 히트 스톱과 카메라 충격을 사용한다.
- 카메라는 플레이어를 `SmoothDamp`로 추적하고 이동 방향 앞쪽에 작은 여백을 둔다.
- 카메라 충격은 렌더링 순간에만 더해 실제 월드 좌표와 픽셀 판정을 움직이지 않는다.
- 화면에 동시 표시되는 섬광, 잔상과 피해 숫자는 풀과 예산으로 제한한다.

## 8. 성능과 모바일 안전

- 프레임 배열과 모션 프로필은 생성 시 할당하고 `Update`에서 새 컬렉션을 만들지 않는다.
- 몬스터별 `Animator Controller`를 대량 생성하지 않고 가벼운 공용 프레임 플레이어를
  사용한다.
- 보이지 않는 먼 개체는 프레임 갱신 빈도를 낮출 수 있지만 논리 이동과 판정은 유지한다.
- Point 필터, 무압축, PPU 64와 Pixel Perfect Camera 규칙을 유지한다.
- Android 기준 동시 적 48개에서 애니메이션이 프레임 드롭을 만들지 않아야 한다.

## 9. 검증

- 정지, 출발, 방향 전환, 대각 이동과 정지를 반복해 발 미끄러짐과 순간 뒤집힘을 확인한다.
- 동일 몬스터 여러 마리를 생성해 애니메이션 위상이 겹치지 않는지 확인한다.
- 일반, 엘리트, 보스의 보폭과 피격 반응이 즉시 구분되는지 확인한다.
- 각 무기의 판정 프레임과 접촉 섬광·피해 숫자 발생 프레임이 일치하는지 확인한다.
- 시각적 바운스와 스쿼시 중에도 픽셀 마스크 접촉 테스트가 동일하게 통과해야 한다.
- Unity Console 컴파일 오류가 없어야 한다.
- 관련 EditMode 테스트와 짧은 Gameplay PlayMode 스모크 검증을 수행한다.
- 360 x 800 기준 Game 뷰와 실제 Android 종횡비에서 움직임과 픽셀 선명도를 확인한다.

## 10. 완료 기준

- 주인공과 주요 몬스터가 한 프레임 그림처럼 미끄러지지 않는다.
- 군집 몬스터가 같은 박자로 흔들리지 않는다.
- 엘리트와 보스가 크기 외에도 움직임의 무게로 구분된다.
- 8종 무기의 이동 리듬이 서로 다르고 판정과 연출이 일치한다.
- 피격, 처치와 강한 공격의 반응이 명확하지만 전투 가독성을 가리지 않는다.
- 기존 무기 성장, 잠재 옵션, 피해 숫자와 픽셀 접촉 규칙이 유지된다.

# 모듈형 조립식 로비 UI 개편 설계

## 1. 목표

현재 로비를 첨부된 조선 판타지 모바일 UI 시안의 정보 위계와 색감에 맞게 개편한다.
기존 계정 성장, 수련, 출전, 무기 연구 기능과 저장 데이터는 그대로 유지하되,
화면을 실행 중에 코드로 조립하는 구조를 작은 UI 부품 프리팹을 씬에서 조립하는 구조로 바꾼다.

완성된 `Lobby` 씬은 Unity의 Scene 뷰에서 배경, 헤더, 메뉴, 각 세부 화면을 직접 볼 수 있어야 한다.
디자이너는 공통 부품은 Prefab Mode에서, 화면별 위치와 크기는 Lobby 씬에서 수정할 수 있어야 한다.

## 2. 확정된 사용자 결정

- 메인 로비에는 `수련`, `출전`, `연구`의 큰 메뉴 버튼 세 개를 둔다.
- 세부 화면은 공통 `뒤로가기` 버튼으로 메인 로비에 복귀한다.
- 기존 하단 탭 내비게이션은 제거한다.
- 메인 로비에서 `환도 비검 연구` 제목과 연구 설명은 제거한다.
- 하나의 거대한 완성형 UI 프리팹보다 헤더, 메뉴 카드, 행, 버튼 같은 UI 에셋을 부품처럼 조립한다.
- 새로운 게임 기능을 임의로 추가하지 않고 현재 실제로 동작하는 기능만 표시한다.

## 3. 선택한 접근법

### 3.1 모듈형 authored UI

`Lobby.unity`에 화면의 정적 계층을 저장하고, 다음과 같은 작은 연결 프리팹을 조립한다.

- 공통 헤더
- 화면 제목과 뒤로가기
- 메인 메뉴 카드
- 정보 요약 카드
- 수련 능력 행
- 난이도 카드
- 무기 선택 카드
- 연구 단계 행
- 진행 바
- 주요 행동 버튼
- 보조 행동 버튼
- 잠금 오버레이

각 부품은 배경, 테두리, 아이콘 자리, 텍스트 자리와 필요한 View 컴포넌트를 소유한다.
부품 안에 특정 계정 수치나 무기 이름을 고정하지 않는다. 프레젠터가 저장 데이터에서 값을 읽어
직렬화된 View 참조에 주입한다.

### 3.2 선택하지 않은 접근법

- 기존 런타임 UI에 외형만 덧씌우지 않는다. Scene 뷰 편집성과 시안 충실도가 낮기 때문이다.
- 외부 Asset Store UI 패키지에 프로젝트를 종속시키지 않는다. 현재 9-slice 자산과 PixelLab 보강만으로
  필요한 조선풍 시각 언어를 만들 수 있고, 불필요한 라이선스 및 재연결 비용을 피할 수 있다.
- 전체 화면을 하나의 거대한 프리팹으로 만들지 않는다. 작은 수정도 전체 프리팹에 결합되고
  재사용성과 화면별 배치 조정이 나빠지기 때문이다.

## 4. 화면 구조

### 4.1 공통 셸

모든 로비 화면에는 다음 요소가 고정된다.

1. 배경: 기존 픽셀 조선 건물 및 안뜰 배경
2. 상단 헤더: 계정 레벨, 이름, 계정 경험치 바, 엽전 아이콘과 수량, 설정 버튼
3. 중앙 콘텐츠 영역: 메인 허브 또는 한 개의 세부 화면
4. 세부 화면의 뒤로가기 버튼
5. 설정 오버레이: 배경 음악과 효과음 조절

콘텐츠 영역에는 불투명한 먹색 패널을 사용한다. 배경이 비쳐 글자가 흐려지는 반투명 패널은 사용하지 않는다.

### 4.2 메인 로비

메인 로비는 연구 화면처럼 보이지 않는 기능 허브다.

- 중앙에 `수련`, `출전`, `연구` 메뉴 카드 세 개를 가로 또는 화면 폭에 맞는 3열로 배치한다.
- `출전`은 게임의 핵심 행동이므로 진홍색 내부와 밝은 금색 테두리로 가장 강하게 표현한다.
- `수련`과 `연구`는 어두운 먹색 내부와 금색 테두리를 사용한다.
- 각 메뉴 카드에는 픽셀 아이콘, 메뉴명, 한 줄 설명만 둔다.
- 메뉴 아래에는 `현재 출전` 정보 한 줄을 둔다.
  - 선택 스테이지
  - 선택 난이도
  - 시작 무기
- `환도 비검 연구`, 연구 단계, 연구 필요 업적은 메인 로비에 표시하지 않는다.
- 장식용 문구나 아직 없는 기능으로 이동하는 버튼은 만들지 않는다.

### 4.3 수련 화면

- 상단에 뒤로가기, 수련 아이콘, `수련` 제목과 짧은 설명을 둔다.
- 여섯 수련 항목을 한 줄짜리 행으로 표시한다.
  - 아이콘
  - 항목명
  - 현재 진행 바
  - 현재 단계 / 최대 단계
- 선택한 항목 아래에는 현재 효과, 강화 후 효과, 비용 또는 다음 계정 레벨 제한을 나란히 보여준다.
- 하단에 진홍색 `수련하기`와 어두운 `전체 초기화` 버튼을 둔다.
- 기존 계정 레벨당 수련 한도, 비용, 효과, 환불 규칙을 변경하지 않는다.

### 4.4 출전 화면

- 상단에 뒤로가기, 출전 아이콘, `출전` 제목을 둔다.
- 현재 스테이지 이름과 좌우 스테이지 이동 버튼을 한 영역에 배치한다.
- 중앙에는 기존 픽셀 한연화를 원형 프레임 안에 표시한다.
- `보통`, `흉조`, `대흉` 난이도 카드를 배치한다.
  - 선택: 진홍색 내부와 밝은 금색 이중 테두리
  - 비선택: 먹색 내부와 낮은 채도 금색 테두리
  - 잠김: 낮은 채도, 중앙 자물쇠, 카드 내부에만 들어오는 대각선 봉인선
- 시작 무기 카드에는 아이콘과 이름을 표시하고 눌렀을 때 기존 무기 선택 화면을 연다.
- 하단의 가장 큰 버튼은 `출전 시작`이다.
- 스테이지 해금, 난이도 해금, 시작 무기 저장과 Gameplay 이동 규칙은 유지한다.

### 4.5 연구 화면

- 상단에 뒤로가기, 연구 아이콘, `무기 연구` 제목을 둔다.
- 보유 무기 여덟 개는 작은 선택 아이콘 그리드로 유지한다.
- 선택된 무기의 아이콘, 이름, 숙련도 진행 바를 첫 정보 카드에 크게 표시한다.
- 기존 세 운용법 단계는 세 개의 독립 연구 행으로 표시한다.
  - 단계명
  - 현재 상태
  - 핵심 효과
  - 필요한 숙련도와 엽전
  - 가능한 경우 `해금` 또는 `장착` 행동
- 잠긴 단계는 자물쇠와 정확한 해금 조건을 표시한다.
- 이미 존재하는 숙련도, 엽전 지불, 순차 해금, 장착 규칙을 변경하지 않는다.

## 5. 시각 체계

### 5.1 팔레트

- 본문 패널: 짙은 남흑색과 먹색
- 일반 글자: 밝은 한지색
- 제목과 테두리: 따뜻한 금색
- 핵심 행동과 선택: 진홍색
- 비활성 및 잠김: 낮은 채도의 회갈색
- 경험치 및 진행 바: 현재 계정 헤더의 선명한 녹색 계열

금색은 제목, 선택 테두리, 중요한 수치에만 사용한다. 모든 요소를 금색으로 둘러 시각적 우선순위가
사라지지 않게 한다.

### 5.2 프레임과 버튼

- 모든 패널과 버튼은 pixel-perfect 9-slice를 사용한다.
- 프레임 가장자리는 가늘고 선명해야 하며 큰 건축물처럼 콘텐츠를 압도하면 안 된다.
- 주요 버튼은 Normal, Highlighted, Pressed, Disabled 상태를 모두 가진다.
- 선택 상태는 색만 바꾸지 않고 테두리 밝기와 내부색을 함께 바꾼다.
- 최소 터치 높이는 기준 해상도에서 약 56dp, 작은 아이콘 버튼은 최소 48dp 영역을 확보한다.

### 5.3 픽셀 자산

기존 `PremiumJoseon` 9-slice와 로비 배경, 한연화, 엽전, 톱니, 화살표, 무기 아이콘을 우선 재사용한다.
다음 자산만 부족할 때 PixelLab으로 같은 팔레트와 선 굵기로 제작한다.

- 수련 여섯 종 아이콘
- 수련, 출전, 연구 대표 메뉴 아이콘 보강
- 카드 내부형 봉인선 및 자물쇠 오버레이
- 연구 소재 아이콘이 실제 정보 전달에 필요할 경우의 소형 아이콘

이미지 안에는 글자를 굽지 않는다. 모든 한글은 TextMeshPro로 표시한다.

## 6. Unity 구조

### 6.1 씬 소유권

`Lobby.unity`가 다음 정적 구조를 소유한다.

```text
Lobby Camera
Lobby Canvas
  Safe Area
    Background
    Common Header
    Home Page
    Training Page
    Patrol Page
    Research Page
    Settings Overlay
EventSystem
```

각 페이지 아래의 행과 카드들은 모듈형 UI 프리팹의 연결 인스턴스다. 정상 씬을 실행할 때
`LobbyBootstrap`이 이 계층을 삭제하거나 새로 만들지 않는다.

### 6.2 코드 역할

- `LobbyBootstrap`: 저장 세션을 로드하고 공통 헤더와 각 프레젠터를 연결한다.
- `LobbyNavigationPresenter`: `Home`, `Training`, `Patrol`, `Research` 상태 전환과 뒤로가기를 담당한다.
- `PatrolPresenter`: 스테이지, 난이도, 시작 무기, 출전만 담당한다.
- `WeaponResearchPresenter`: 무기와 운용법 연구 데이터만 담당한다.
- `CommonTrainingPresenter`: 수련 선택, 구매, 초기화만 담당한다.
- View 컴포넌트: 직렬화된 Text, Image, Button, Slider 참조만 제공하고 도메인 계산을 소유하지 않는다.
- `LobbyUiFactory`: 런타임 화면 생성 책임을 제거한다. 필요한 경우 Editor builder에서 최초 부품 생성에만 사용한다.

기존의 공개 데이터 형식, 저장 형식, 도메인 서비스 호출은 유지한다.

### 6.3 편집 도구

- `LobbySceneBuilder`는 빈 프로젝트에서 모듈 부품과 Lobby 씬을 처음 구성하거나 명시적인 재구축 명령에만 사용한다.
- 이미 유효한 연결 프리팹과 씬 배치를 정상 실행 중에 덮어쓰지 않는다.
- 열린 Lobby 씬이 수정된 상태라면 재구축을 거부하고 저장 여부를 먼저 확인한다.
- `LobbyEditingTools`는 Lobby 씬 열기, 선택한 모듈 프리팹 열기, 명시적 재구축 메뉴를 제공한다.

## 7. 데이터 흐름과 오류 처리

1. 로비 진입 시 `MetaGameSession`을 한 번 바인딩한다.
2. 헤더와 세 페이지는 같은 세션의 읽기 모델을 사용한다.
3. 구매, 해금, 장착, 시작 무기 변경 후 관련 화면과 헤더만 갱신한다.
4. 잠긴 항목과 비용 부족 버튼은 도메인 호출 전에 비활성 또는 명확한 상태로 표시한다.
5. 도메인 명령이 실패하면 저장 데이터를 변경하지 않고 해당 페이지의 한글 피드백 영역에 이유를 표시한다.
6. 중복 클릭으로 구매나 출전 요청이 두 번 실행되지 않게 기존 라우팅 및 버튼 잠금 규칙을 유지한다.
7. 깨진 인코딩 문자열은 모두 정상 UTF-8 한글로 교체하고 테스트도 정상 한글을 계약으로 삼는다.

## 8. 반응형 배치

- 디자인 기준 해상도는 1080×1920 세로 화면이다.
- 필수 검증 해상도는 720×1280, 1080×1920, 1080×2340이다.
- 상단 헤더와 화면 여백은 Safe Area를 따른다.
- 본문은 최대 폭을 두어 긴 화면에서 과도하게 넓어지지 않게 한다.
- 720×1280에서도 각 화면의 핵심 행동 버튼이 스크롤 없이 보여야 한다.
- 긴 연구 설명은 행 내부에서 정해진 줄 수로 줄바꿈하고 테두리를 침범하지 않아야 한다.

## 9. 검증 전략

### 9.1 EditMode 계약

- Lobby 씬에 공통 헤더, 네 페이지, 설정 오버레이가 하나씩 존재한다.
- 각 화면 부품은 연결된 모듈 프리팹 인스턴스이며 Missing Script가 없다.
- EventSystem과 입력 모듈이 하나씩 존재한다.
- 옛 Bottom Navigation과 거대 `LobbyShell.prefab` 참조는 이관 완료 후 0개다.
- 모든 9-slice 자산은 Point, mipmap 비활성, 압축 비활성, 올바른 border를 유지한다.
- 메인 로비에 `환도 비검 연구` 문자열이 존재하지 않는다.

### 9.2 PlayMode 계약

- 기본 진입 화면은 Home이다.
- 세 메뉴 버튼은 각 페이지를 열고 각 뒤로가기 버튼은 Home으로 돌아온다.
- 동시에 활성화되는 페이지는 하나뿐이다.
- 헤더의 계정 레벨, 경험치, 엽전과 설정이 모든 페이지에서 유지된다.
- 수련 구매와 초기화, 연구 해금과 장착, 스테이지·난이도·무기 선택과 출전이 기존 규칙대로 동작한다.
- 선택, 비선택, 잠김, 비활성 버튼이 정확한 semantic skin을 사용한다.
- 반복 초기화가 리스너나 UI 인스턴스를 중복 생성하지 않는다.

### 9.3 시각 검수

각 검증 해상도에서 Home, Training, Patrol, Research, Settings 화면을 캡처한다.

- 배경과 패널이 명확히 분리된다.
- 모든 한글과 수치가 프레임 안에서 읽힌다.
- 선택된 메뉴와 난이도를 1초 안에 구분할 수 있다.
- 잠금 봉인선과 자물쇠가 카드 밖으로 나오지 않는다.
- 핵심 행동은 화면마다 하나만 가장 강하게 보인다.
- 공통 부품의 선 굵기, 모서리, 금색이 화면마다 일치한다.

## 10. 성능과 안정성

- 로비 진입 때 프레임별 Sprite 로드, UI 생성, 폰트 생성 또는 Resources 검색을 반복하지 않는다.
- 페이지 전환은 기존 오브젝트 활성 상태만 전환한다.
- 프로그레스 바와 텍스트는 데이터 변경 시에만 갱신한다.
- 화면 전환 시 이벤트 리스너가 누적되지 않는다.
- 모바일 빌드에서 불필요한 UI 오버드로우를 줄이기 위해 투명 대형 패널을 겹치지 않는다.

## 11. 마이그레이션과 정리

- 현재 작업 트리의 미완성 `Lobby.unity`, `LobbyShell.prefab`, 스킨, 잠금 컴포넌트 변경을 먼저 감사해
  유효한 수정은 새 구조에 흡수한다.
- 기존 거대 LobbyShell과 런타임 생성 경로는 새 씬, 테스트, 캡처가 모두 통과한 뒤 참조 0건을 확인하고 제거한다.
- 생성된 캡처, 폰트 아틀라스, 무관한 아트 `.meta` 변경은 의도한 소스 커밋과 분리한다.
- 저장 데이터 마이그레이션은 하지 않는다. 화면 구조만 바뀌고 데이터 모델은 유지된다.

## 12. 범위 제외

- 새로운 재화, 상점, 미션, 친구, 가방, 에너지 시스템
- 신규 스테이지 또는 전투 밸런스 변경
- 계정 레벨과 수련 수치 재설계
- 무기 숙련도 및 운용법 해금 규칙 변경
- 로비용 비픽셀 캐릭터 일러스트 추가
- 외부 Asset Store 패키지 의존성 추가

## 13. 완료 기준

- 시안의 어두운 조선풍, 금색 테두리, 진홍색 핵심 행동 위계가 네 화면에 일관되게 적용된다.
- 메인 로비에는 세 메뉴와 현재 출전 정보만 있고 연구 설명이 없다.
- Unity Scene 뷰에서 전체 Lobby 배치를 보고 위치와 크기를 직접 조정할 수 있다.
- 공통 부품은 Prefab Mode에서 한 번 수정해 모든 사용처에 반영된다.
- 기존 수련, 출전, 연구, 설정 기능과 저장 데이터가 회귀 없이 동작한다.
- 필수 세 해상도 캡처, 관련 자동 테스트, 전체 테스트, Android 개발 빌드가 통과한다.

# 스테이지 난이도 및 해금 구조 설계

## 1. 목표

서로 다른 세 장의 스테이지와 각 장의 `보통`, `흉조`, `대흉` 난이도를 결합해 총 아홉 개의 도전 노드를 만든다. 플레이어는 스테이지를 처음부터 순서대로 경험하면서도, 한 장을 클리어한 뒤에는 다음 장소로 진행하거나 익숙한 장소의 상위 난이도에 도전할 수 있다.

이번 설계는 다음 항목만 다룬다.

- 스테이지와 난이도의 식별 방식
- 최초 해금 상태와 클리어 기반 해금 규칙
- 로비의 스테이지·난이도 선택 흐름
- 클리어 기록과 최초 보상 저장 기준
- 난이도별 전투·보상 배율의 공통 기반

2장과 3장의 실제 배경, 몬스터 구성, 15분 웨이브, 중간보스 및 최종보스 패턴은 각각 별도 설계와 구현 단위로 진행한다. 이번 작업에서 임시 전투 콘텐츠를 복제해 새 스테이지처럼 보이게 만들지 않는다.

## 2. 스테이지 구성

초기 장 구성은 다음과 같다.

| 장 | 이름 | 핵심 전투 성격 |
|---|---|---|
| 1장 | 귀곡 들판 | 다수의 쥐와 귀신 무리를 상대하며 이동과 광역 공격을 익힌다. 현재 15분 스테이지가 기준이다. |
| 2장 | 도깨비 고개 | 느리고 단단한 도깨비, 방패병, 돌진형 적을 중심으로 관통과 강한 단일 공격을 요구한다. |
| 3장 | 월식 왕릉 | 원거리 귀신, 무당, 저주 장판을 중심으로 투사체 회피와 위험지역 관리를 요구한다. |

각 장은 `보통`, `흉조`, `대흉` 세 난이도를 가진다. 로비에서는 장과 난이도를 별도 단계로 선택하지만, 저장과 실행에서는 `(StageId, Difficulty)` 조합 하나가 전투 노드를 식별한다.

## 3. 해금 규칙

### 3.1 최초 상태

- 신규 계정은 `1장 귀곡 들판 · 보통`만 선택할 수 있다.
- 나머지 장과 난이도는 잠금 상태로 보인다.
- 잠긴 항목을 숨기지 않고 해금 조건을 한글로 표시한다.

### 3.2 클리어 기반 해금

해금 규칙은 두 문장으로 설명할 수 있어야 한다.

1. 한 장의 `보통`을 최초 클리어하면 같은 장의 `흉조`와 다음 장의 `보통`이 열린다.
2. 한 장의 `흉조`를 최초 클리어하면 같은 장의 `대흉`이 열린다.

마지막 장에는 다음 장이 없으므로 `3장 보통` 클리어 시 `3장 흉조`만 열린다. `대흉` 클리어는 추가 전투 노드를 열지 않는다.

```text
1장 보통
 ├─ 2장 보통
 └─ 1장 흉조 ─ 1장 대흉

2장 보통
 ├─ 3장 보통
 └─ 2장 흉조 ─ 2장 대흉

3장 보통
 └─ 3장 흉조 ─ 3장 대흉
```

계정 레벨이나 수련 단계는 스테이지 해금 조건으로 사용하지 않는다. 계정 성장은 도전을 돕지만 진행을 강제로 막지 않는다.

### 3.3 해금 상태 계산

별도의 해금 플래그를 여러 개 저장하지 않는다. 완료 기록을 진실의 원천으로 삼아 현재 해금 상태를 계산한다.

- `1장 보통`은 항상 해금된다.
- `N장 보통`은 `N-1장 보통`의 승리 기록이 있으면 해금된다.
- `N장 흉조`는 `N장 보통`의 승리 기록이 있으면 해금된다.
- `N장 대흉`은 `N장 흉조`의 승리 기록이 있으면 해금된다.

이 방식은 저장 데이터가 부분적으로 손상되거나 이후 장이 추가되어도 서로 모순되는 잠금 플래그가 생기지 않게 한다.

## 4. 난이도 역할과 초기 배율

모든 난이도는 같은 장의 15분 흐름과 고유 정체성을 유지한다. 상위 난이도는 체력만 올리는 복제가 아니라 적 조합, 정예 압박, 보스 패턴을 함께 강화한다.

| 항목 | 보통 | 흉조 | 대흉 |
|---|---:|---:|---:|
| 적 체력 배율 | 1.00 | 1.35 | 1.75 |
| 적 접촉·공격 피해 배율 | 1.00 | 1.15 | 1.30 |
| 웨이브 밀도 배율 | 1.00 | 1.10 | 1.20 |
| 엽전 보상 배율 | 1.00 | 1.35 | 1.75 |
| 계정 경험치 배율 | 1.00 | 1.25 | 1.50 |
| 무기 숙련도 배율 | 1.00 | 1.20 | 1.40 |

- `보통`은 해당 장의 몬스터 역할과 보스 패턴을 소개한다.
- `흉조`는 정예 비중을 높이고 해당 장의 강화 규칙 하나와 보스 강화 패턴을 사용한다.
- `대흉`은 정예 혼합 웨이브, 강화 규칙 두 개, 보스 2페이즈를 사용한다.
- 경고 시간과 회피 가능성은 난이도와 관계없이 보장한다. 대흉도 피할 수 없는 피해로 어렵게 만들지 않는다.
- 위 배율은 최초 구현 기준값이며 자동 테스트의 고정 계약이 아니라 플레이 테스트용 조정 데이터다. 해금 규칙과 저장 계약은 배율 변경과 분리한다.

## 5. 보상 원칙

### 5.1 보통 최초 클리어

- 다음 장 보통 및 같은 장 흉조 해금
- 해당 장과 연결된 무기 연구 또는 운용법 하나의 해금 자격 부여
- 일반 엽전, 계정 경험치, 실제 사용 무기 숙련도 지급

### 5.2 흉조 최초 클리어

- 같은 장 대흉 해금
- 해당 장의 추가 연구 단계 또는 운용법 해금 자격 부여
- 보통보다 높은 엽전, 계정 경험치, 무기 숙련도 지급

### 5.3 대흉 최초 클리어

- 필수 전투 성능 대신 특별 칭호, 테두리, 기록 표식 같은 명예 보상을 우선한다.
- 높은 엽전, 계정 경험치, 무기 숙련도를 지급한다.
- 대흉을 클리어하지 못해도 다음 기본 스테이지 진행이나 핵심 무기 사용이 막히지 않는다.

반복 클리어에서도 난이도별 자원 배율은 유지하지만 최초 해금 보상은 다시 지급하지 않는다. 정산은 기존 원자적 저장 흐름에 포함되어 중복 지급이나 클리어 기록만 저장되는 부분 성공이 없어야 한다.

## 6. 로비 선택 흐름

출전 화면은 다음 순서로 동작한다.

1. 현재 선택된 장의 이름과 대표 이미지를 표시한다.
2. 좌우 화살표 또는 장 선택 카드를 통해 1장부터 3장까지 이동한다.
3. 장 아래에 `보통`, `흉조`, `대흉` 난이도 버튼을 표시한다.
4. 선택 가능한 난이도는 조선풍 금색 강조를 사용하고, 잠긴 난이도는 채도를 낮춘다.
5. 잠긴 버튼을 누르면 출전하지 않고 정확한 조건을 짧게 표시한다.
6. 출전 버튼에는 선택된 장과 난이도를 함께 표시한다.

잠금 안내 문구는 다음으로 고정한다.

- 잠긴 다음 장 보통: `이전 장 보통 승리 시 해금`
- 잠긴 흉조: `이 장 보통 승리 시 해금`
- 잠긴 대흉: `이 장 흉조 승리 시 해금`

현재 선택이 저장 데이터 갱신 후 잠기게 된 경우에는 자동으로 가장 최근의 선택 가능한 난이도로 되돌린다. 잠긴 조합으로 출전을 시도하면 전투 씬을 열지 않고 동일한 안내 문구를 보여준다.

## 7. 데이터 및 책임 경계

### 7.1 도메인 모델

- `StageId`: 장을 식별하는 안정적인 값. 표시 이름이나 배열 순번을 저장 키로 사용하지 않는다.
- `StageDifficulty`: `Normal`, `Omen`, `GreatOmen` 세 값만 가진다.
- `StageClearRecord`: 해당 조합의 최초 승리 여부, 최고 생존 시간, 최고 처치 수, 최고 도달 레벨을 보관한다.
- `StageUnlockRules`: 완료 기록을 입력받아 잠금 여부와 잠금 안내 사유를 계산한다.
- `StageDifficultyProfile`: 전투와 보상 배율, 정예 단계, 보스 강화 단계를 제공한다.

도메인 계산은 Unity 오브젝트 없이 테스트할 수 있는 순수 C#으로 유지한다.

### 7.2 저장

- 현재 저장 스키마에 `(StageId, Difficulty)`별 클리어 기록 컬렉션을 추가하고 스키마 버전을 한 단계 올린다.
- 이전 저장 데이터는 기존 1장 전투 승리 기록이 확인되면 `1장 보통` 승리로 이관한다.
- 과거 승리 여부를 신뢰할 필드가 없다면 `1장 보통`만 열린 신규 상태로 이관하며 엽전, 숙련도, 계정 경험치, 수련은 그대로 보존한다.
- 알 수 없는 미래의 스테이지 기록은 로드 중 삭제하지 않고 보존하되 현재 UI에는 표시하지 않는다.

### 7.3 실행 연결

- 로비는 선택된 `(StageId, Difficulty)`를 출전 요청에 전달한다.
- 전투 구성기는 `StageId`로 스테이지 정의를, `Difficulty`로 난이도 프로필을 선택한다.
- 결과 정산은 승리한 조합의 기록 갱신, 최초 클리어 보상, 일반 정산을 하나의 저장 트랜잭션으로 처리한다.
- 2장과 3장의 전투 정의가 아직 없으면 해당 장은 개발 중 상태로 취급하며 저장상 해금되었더라도 출전 버튼을 비활성화한다. 가짜로 1장 전투를 재사용하지 않는다.

## 8. 오류 처리

- 저장된 장 또는 난이도 값이 잘못되면 `1장 보통` 선택으로 복구한다.
- 클리어 기록이 중복되어 있으면 동일 조합끼리 병합하고 승리 여부는 논리합, 최고 기록은 최댓값을 사용한다.
- 난이도 프로필이 누락되면 출전을 거부하고 사용자에게 `출전 정보를 불러오지 못했습니다`라고 표시한다.
- 전투 정의가 없는 장은 `아직 준비 중인 지역입니다`라고 표시한다.
- 정산 저장이 실패하면 최초 보상과 클리어 기록을 메모리에도 확정하지 않고 기존 저장 상태로 되돌린다.

## 9. 테스트 전략

### EditMode

- 신규 계정에서 `1장 보통`만 해금되는지 확인
- 각 장 보통 승리 시 같은 장 흉조와 다음 장 보통이 열리는지 확인
- 3장 보통 승리 시 존재하지 않는 4장이 생성되지 않는지 확인
- 각 장 흉조 승리 시 같은 장 대흉만 열리는지 확인
- 계정 레벨과 수련 단계가 해금 계산에 영향을 주지 않는지 확인
- 난이도별 초기 전투·보상 프로필 값 확인
- 중복 기록 병합, 잘못된 선택 복구, 이전 저장 이관 확인
- 최초 클리어 보상이 한 번만 지급되는지 확인
- 정산 실패 시 보상과 기록 모두 롤백되는지 확인

### PlayMode

- 로비에서 장과 난이도 선택 상태 및 잠금 안내 확인
- `1장 보통` 승리 후 로비 복귀 시 `2장 보통`과 `1장 흉조`가 즉시 열리는지 확인
- 잠긴 난이도 및 전투 정의가 없는 장으로 출전할 수 없는지 확인
- 출전 요청이 선택한 장과 난이도를 전투 구성기에 전달하는지 확인
- 승리 결과 화면에 장, 난이도, 최초 해금 결과가 한글로 표시되는지 확인

### 회귀 검증

- 기존 1장 15분 타임라인과 보스 공격 테스트 유지
- 기존 계정 경험치, 수련, 엽전, 무기 숙련도 정산 테스트 유지
- Unity EditMode와 PlayMode 전체 실행
- Android 개발 빌드 및 세로 화면 로비 육안 확인

## 10. 완료 조건

- 신규 계정은 `1장 보통`만 출전할 수 있다.
- `1장 보통` 승리 후 `2장 보통`과 `1장 흉조`가 동시에 해금된다.
- 모든 장에서 `보통 -> 흉조 -> 대흉`의 독립적인 난이도 진행이 성립한다.
- 다음 장 보통 진행은 이전 장 대흉이나 계정 레벨을 요구하지 않는다.
- 잠긴 항목은 숨지 않고 정확한 한글 해금 조건을 보여준다.
- 난이도별 전투와 보상 배율이 하나의 프로필에서 제공된다.
- 최초 클리어 보상과 일반 정산 및 클리어 기록이 원자적으로 저장된다.
- 기존 저장 데이터의 엽전, 무기 숙련도, 계정 경험치, 수련 진행이 손실되지 않는다.
- 2장과 3장 콘텐츠가 준비되기 전에는 1장 복제본으로 출전시키지 않는다.
- 관련 EditMode·PlayMode 테스트와 Android 개발 빌드가 통과한다.
